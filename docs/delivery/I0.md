## Critérios de aceite I0-r1

1. Um nome válido enviado pela página passa pela API C# e é salvo no PostgreSQL; nenhum mock ou armazenamento somente no navegador comprova esse requisito.
2. Após recarregar a página, registro e ID permanecem disponíveis pela API. Reiniciar a API não apaga os dados.
3. Nome vazio ou somente espaços é recusado pela API e a interface apresenta a validação sem criar registro inválido.
4. Falha de comunicação/salvamento é apresentada sem sucesso falso; dados digitados são preservados para nova tentativa. Não repetir envio automaticamente sem definir como evitar duplicação.
5. É possível preparar banco vazio pelas migrações e repetir a demonstração seguindo instruções documentadas.
6. Segredos de conexão ficam fora do frontend e dos arquivos versionados; exemplos de configuração não contêm credenciais reais.

### Contrato mínimo I0-r1

| Operação | Entrada/saída | Comportamento |
| --- | --- | --- |
| POST `/api/exercises` | JSON `{ "name": "Agachamento de teste" }` → `{ "id": "<uuid>", "name": "Agachamento de teste" }` | 201 somente após persistir; UUID gerado no servidor; sem Location para uma rota de detalhe inexistente |
| GET `/api/exercises` | Array de objetos id/name; banco vazio retorna `[]` | 200; consulta real sem cache no cliente/Next.js; ordenação por name e id para desempate, conforme collation do banco, sem promessa de ordenação linguística específica |
| Entrada inválida | Nome ausente, null, vazio, só espaços, tipo incompatível ou JSON malformado | 400; erros compreensíveis e campo `name` quando aplicável; formato Problem Details para erros, incluindo erros de binding |
| Falha inesperada | Erro de persistência ou API | 5xx com Problem Details genérico, sem connection string/SQL/stack trace; detalhe técnico apenas no log local sem dados sensíveis |

Sem GET por ID, edição, exclusão, busca/paginação ou campos opcionais neste recorte. Listagem integral é suficiente para poucos dados sintéticos; rever paginação antes de catálogo real. ID não deriva do nome. Normalização confirmada (D73): trim das extremidades; preservar conteúdo interno/acentos/caixa. Nomes iguais podem coexistir com IDs distintos no teste; isso não decide a política final de duplicados do catálogo. Não há limite específico de caracteres de produto definido para este recorte; não acrescentar número arbitrário.

### Interface e falhas

Rota `/exercises`, rótulo Nome associado ao campo, botão Salvar e lista com estado vazio. Mostrar carregamento e erro de listagem separadamente; erro não se apresenta como lista vazia. Durante POST, desabilitar novo envio. Em 201, apresentar sucesso, limpar campo e incluir o objeto retornado pelo servidor; recarregar comprova leitura do banco. Falha posterior de GET deve ser apresentada como falha de atualização da lista, sem negar um POST já confirmado.

Em erro de validação ou comunicação, manter o texto digitado e permitir tentativa explícita. Não repetir POST automaticamente. Quando não houver resposta, informar que não foi possível confirmar o salvamento e orientar consultar a lista antes de reenviar: o servidor pode ter salvo antes da conexão cair. I0 não garante ausência de duplicação entre tentativas nessa situação; garantia exigiria protocolo de idempotência adicional.

| Nível | Casos e evidência esperada |

Sem meta de cobertura nem unitários para getters; adicionar unitários apenas diante de regra própria relevante. Reinício de processos/volume é evidência complementar, não repetição de todo o E2E.
